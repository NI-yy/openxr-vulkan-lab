- Quest 2（Android 14、security patch 2026-06-04）、USB ADB 接続。
- Java 21、ホストのシーンテスト、模擬ADBによる連続測定テスト、Debug APK ビルドは `./tools/verify.ps1` で成功。Gradle の `checkCubeShaders` も通過。
- 使用した APK の SHA-256: `D6CFEA2581686457EC794455F8E6250E34C49EAAC5C15CDD5E03BA8FD079937E`。Validation Layer は Khronos の Android binaries `1.4.341.0` に含まれる arm64-v8a 版を使用。
- 計測全体は `manifest.json` の `status=passed`。4条件とも 300 フレームのウォームアップと 1800 フレームの計測を完了し、要求した描画方式・FFR が選択された。各条件で `validation_off_confirmed=True`、サーマル状態は開始時と終了時とも `0`。

## Vulkan Validation Layer

最初の起動では `validation=on selected=on` だったが、Quest の OpenXR ランタイムが有効化する `VK_KHR_surface_protected_capabilities` に必要な `VK_KHR_get_surface_capabilities2` が不足し、`VUID-vkCreateInstance-ppEnabledExtensionNames-01388` が出た。[最初のログ](measurements/20261012-quest2-issues10-13/validation-on.txt)を参照。

`renderer.cpp` で Validation 有効時に利用可能な `VK_KHR_surface` と `VK_KHR_get_surface_capabilities2` をインスタンス拡張に含めるよう修正した。再ビルド後は `requested=on selected=on` と Debug Utils messenger の有効化を確認し、取得したログに Validation Error / Warning はなかった。[修正後のログ](measurements/20261012-quest2-issues10-13/validation-on-fixed.txt)を参照。

`validation=off` では `requested=off selected=off layer=none` とフレーム進行を確認した。[off のログ](measurements/20261012-quest2-issues10-13/validation-off.txt)を参照。レイヤー非同梱 APK で `validation=on` とした場合は `not found among 0 instance layers`、`selected=off` を記録し、通常描画が継続した。[非同梱時のログ](measurements/20261012-quest2-issues10-13/validation-unavailable.txt)を参照。連続計測では毎条件 Validation off を確認した。
